# 毕业设计实验验证报告

## 研究问题与材料

依照开题报告，本实验检查课程资料检索、同一模型下 RAG 与多 Agent 方法的回答质量，并分别检查图片识别与代码静态分析。资料为本机已导入的 44 份 PPT、88 份 DOCX 和 628 页 PPT 图像索引。实验前冻结了资料、Top 5 检索结果及图片哈希；快照 SHA-256 为 `a6332da8d25ed6e9c0500a6e51fb3fe86350bc96fa091f533020735ee1b5011e`。

案例集含 30 道文本题（知识 8、操作 12、复合 10），覆盖四个课程模块；另有 6 道图片题、6 道代码题。每题预先标注来源、关键答案点、不可确认项及评分规则。题目、课件证据、逐条回答和复核备注留在本机；公开的[案例索引](../evaluation/cases-manifest.json)只列匿名 ID、类型及模块。

## 方法与评分

所有组使用相同的 `QWEN_MODEL`。30 道文本题分别运行单 Agent＋RAG（冻结的 Top 5 课程片段）和单 Agent 无 RAG；10 道复合题另运行课程问答 Agent、实验指导 Agent、整合 Agent 各一次。图片和代码题各调用一次。计划和完成的逻辑请求均为 102 次，全部返回成功；上限为 120 次。每次请求前将 `start` 事件写入账本，未完成请求仍占额度，续跑不会重发相同任务。当前运行器关闭 SDK 自动重试；本轮实测进程启动时仍使用旧版客户端配置，底层允许一次自动重试。账本没有失败记录，但不能从账本证明底层从未重试。因此 **102 是可核验的逻辑请求数，不能严格证明本轮底层尝试次数**；当前版本禁用自动重试，避免今后出现账本外重试。

检索 Recall@5 要求人工标注的同一文件、同一页进入 Top 5；来源文件命中率只要求文件相同。人工逐条复核 82 条最终回答：每题按预设关键点计算覆盖率；存在明确错误或无依据的课程专属断言记为事实错误；引用真正支持关键结论才记为来源支持；未把未证实的效果或细节说成事实才记为不确定性表达正确。引用编号有效率仅检查 `[编号]` 在候选范围内，**不是语义事实核验**。单 Agent 无 RAG 使用不同的通用提示，因此它与 RAG 组之间的差异同时包含提示语变化，不能全归因于检索。人工复核由项目研究者一人完成，未做盲审或独立复标。

## 实测结果

检索的同页 Recall@5 为 **24/30＝80.0%**，同文件命中为 **26/30＝86.7%**。同页未命中的匿名案例为 T01、T05、T12、T13、T15、T16；部分命中的是相邻页或内容相近的 DOCX，因此同页指标比回答可用性更严格。

| 组别 | 案例数 | 关键点覆盖 | 有事实错误 | 来源语义支持 | 引用编号有效 | 平均耗时/题 | 输入/输出 token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 单 Agent＋RAG | 30 | 100.0% | 8/30（26.7%） | 24/30（80.0%） | 30/30 | 6.36 秒 | 48,355 / 15,946 |
| 单 Agent 无 RAG | 30 | 76.7% | 7/30（23.3%） | 不适用 | 不适用 | 8.54 秒 | 14,768 / 19,175 |
| 双 Agent＋整合 | 10 | 100.0% | 2/10（20.0%） | 7/10（70.0%） | 10/10 | 23.48 秒 | 60,926 / 20,815 |
| 图片案例 | 6 | 100.0% | 1/6（16.7%） | 5/6（83.3%） | 不单列 | 5.60 秒 | 15,024 / 2,388 |
| 代码案例 | 6 | 100.0% | 2/6（33.3%） | 不适用 | 不适用 | 10.77 秒 | 1,903 / 4,960 |

双 Agent 只处理复合题，不能直接拿它的 10 题与单 Agent 的全部 30 题比较。在**相同 10 道复合题**上，单 Agent＋RAG、无 RAG、双 Agent 的关键点覆盖依次为 100%、75%、100%；事实错误分别为 3/10、3/10、2/10。双 Agent 的少一次错误不足以说明稳定优于单 Agent＋RAG，且每题需要三次调用，平均耗时 23.48 秒。RAG 组 30/30 的引用编号有效，但仅 24/30 的关键结论获得人工判定的来源语义支持。

图片组均覆盖预设可见要点，1 题因把图中的示例 BaseUrl 说成不可修改而记错；代码组均指出预设错误位置，但有 2 题增加了无依据或过度确定的修复细节。以上成功率只针对这 6＋6 个静态案例，未测试真实设备运行、OCR 扰动或代码执行结果。完整机器汇总见[结果文件](../evaluation/results/summary.json)。

## 典型误差与边界

- **无课程依据时偏向通用经验。** T12 的无 RAG 回答将云平台 `getSensor(deviceId, ApiTag)` 问题转成 Android 本地 `SensorManager`；T26 无 RAG 混淆设备通道配置。这解释了无 RAG 组关键点覆盖偏低，但不能排除提示语不同的影响。
- **检索并不保证事实正确。** T22 的 RAG 回答编造了选择共阳数码管的原因；T28 的 RAG 与双 Agent 回答沿袭资料中的绝对化措辞，声称电流型能“彻底消除”干扰。T25 的资料将 180–290 nm 误称为红外，提示课程原文也需要审核。多 Agent 整合没有自动纠正来源错误。
- **多模态和代码分析会补出未经确认的细节。** V02 将图中的示例地址说成不可修改；C03 将全表删除说成绝对不可撤销；C06 虽正确指出 DI/DO 方向，却指定了未由片段确定的 DO1，课程接线示例使用 DO0。
- **实验外推受限。** 案例是人工精选的本地课程题，样本较小，复核无第二名标注者；延迟受本次网络与服务状态影响。开题报告提及的跨模型比较因没有其他模型接口而未执行。本文仅报告同一模型下的方法对照，不声称跨模型效果或公网生产环境适用性。

## 可追溯性

私有快照保存逐题标准、资料与图像哈希和冻结检索结果；本机追加式账本保存请求配置、模型、时间、用量、状态及逐条输出；私有复核表保存每题评分与理由。公开仓库仅提供运行器、[评分计算代码](../evaluation/metrics.py)、匿名案例索引、汇总值与本报告。公开内容无法独立还原受限课件原文，但本机可按案例 ID 从汇总追溯至冻结证据、原始输出及人工判定。
